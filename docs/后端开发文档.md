## 3. 数据库与增量迁移

### 3.1 强制安全规则

- **禁止**对已有 `erp_wms` 执行 `database/schema.sql`。该文件开头包含 `DROP TABLE IF EXISTS`，会清空已导入数据。
- `inbound_record`、`outbound_record` 是导入的历史数据；它们不再回放、不修改 `stock_balance`，也不补写库存流水。
- 后端结构变化只能经 Alembic 的增量迁移 `0001_add_backend_core`。
- 迁移脚本不会删表或删列；`downgrade()` 被显式禁止，生产回退应使用经过审查的备份恢复。

迁移会新增：`user_account`、`role`、`user_role`、`user_warehouse_scope`、`inbound_order`、`inbound_item`、`outbound_order`、`outbound_item`、`picking_task`、`audit_log`、`idempotency_record`，并为 `stock_balance` 增加 `reserved_quantity`（默认 0）。

## 4. 鉴权、RBAC 与写请求

### JWT

`POST /api/v1/auth/login` 请求：

```json
{"username":"admin","password":"<password>"}
```

响应带 `access_token`。后续请求添加：

```http
Authorization: Bearer <access_token>
```

JWT 包含 `sub`（用户 ID）、`username`、`roles`、`iat`、`exp`。密码以 PBKDF2-SHA256（独立随机盐）存储，绝不存明文。

### RBAC

- `user_account`：账号，可关联既有 `staff`。
- `role` / `user_role`：角色定义与授予。
- `user_warehouse_scope`：可管理仓库范围，已预留给细粒度仓库权限。
- 当前 API 所有业务接口要求登录；服务层和 `require_roles()` 已提供角色校验扩展点。

### 幂等键

每个改变库存或业务状态的 `POST` 请求都必须同时提供：

```http
Idempotency-Key: 9c8e...唯一键
```

系统按“用户 + 幂等键”记录响应。重试同一成功请求会返回第一次结果，不会二次入库、重复预留或重复扣减。

## 5. 库存模型、事务和并发

```text
available_quantity = stock_balance.quantity - stock_balance.reserved_quantity
```

- 入库确认：`quantity += 收货数`，写 `stock_ledger(inbound)` 与 `audit_log`。
- 出库分配：按库位可用库存预留，`reserved_quantity += 分配数`，生成 `picking_task`。
- 拣货确认：任务由 `allocated` 变为 `picked`。
- 出库完成：只允许所有任务为 `picked`；`quantity -= 数量` 且 `reserved_quantity -= 数量`，写 `stock_ledger(outbound)` 与 `audit_log`。

在 MySQL 中，库存读取使用 `SELECT ... FOR UPDATE` 并放在同一数据库事务内，以避免并发超卖。SQLite 单元测试会执行相同业务逻辑，但不能证明 MySQL 行锁并发行为；必须配置独立 `TEST_DATABASE_URL` 后进行 MySQL 集成压测。

## 6. 业务状态机

### 入库单

```text
draft --确认--> confirmed
```

只有 `draft` 可确认；同一入库单不能重复确认。

### 出库单和拣货任务

```text
出库单：draft --分配--> allocated --完成--> completed
拣货任务：allocated --确认--> picked --出库完成--> completed
```

库存不足返回 `409 INVENTORY_INSUFFICIENT`。只有所有任务已确认时，出库单才可完成。

## 8. 错误响应和前端联调

通过 `X-Request-ID` 跟踪每次请求；客户端也可以自行传入该头。当前实现还会把同一 ID 写入运行日志（`backend/logs/app.log` / 控制台）和 `audit_log.request_id`。完整说明见 [`docs/开发文档.md`](./开发文档.md) 第 12 节。应用的统一错误格式：

```json
{
  "code":"INVENTORY_INSUFFICIENT",
  "message":"可用库存不足",
  "request_id":"...",
  "details":{"product_id":1}
}
```

前端联调约定：

1. API 基地址为 `http://127.0.0.1:8000/api/v1`；Vite 前端来源默认允许 `5173`。
2. 登录成功后将 JWT 放在请求 `Authorization` 头，不把密码、数据库 URL 放入前端。
3. 写操作生成并重用唯一 `Idempotency-Key`；网络超时重试时沿用原键。
4. 收到 401 时跳登录，409 时展示业务错误，422 时按 `details.errors` 展示表单校验。

## 11. 盘点、调拨与审批扩展

本扩展使用追加迁移 `0002_stock_count_transfer_approval`，只新增五张表及其索引/约束，不删除既有表或列：`stock_count_order`、`stock_count_item`、`transfer_order`、`transfer_item`、`approval_task`。

本地环境已配置数据库 URL 时，在 `backend` 目录执行：

```powershell
cd backend
alembic upgrade head
pytest -q
```

不得把数据库账号、密码、JWT 或管理员密码写入文档或版本库。生产回退应使用经过审查的备份，而不是 `downgrade()`。

### 11.1 角色规则

- `admin`：可创建、提交、执行、审批，不受仓库范围限制；不能批准自己提交的待审批单。
- `warehouse_operator`：可在授权仓库内创建、编辑、提交盘点和调拨，以及执行已可执行的调拨；不能审批。
- `warehouse_manager`：可在授权仓库内查看并批准/驳回待办；不能创建业务单。
- 创建人/申请人不得审批自己提交的盘点差异或跨仓调拨，违反时返回 `403`。

### 11.2 状态机

盘点：`draft` → `counting` → 无差异 `completed`；有差异 `pending_approval` → `applied` / `rejected`。

调拨：`draft` → 同仓 `executable` → `completed`；跨仓 `pending_approval` → `executable` → `completed`，或 `rejected`。混合同仓/跨仓明细返回 `422 TRANSFER_SCOPE_MIXED`。

审批：`pending` → `approved` / `rejected`。驳回必须填写 1–500 字意见。盘点批准时才调整库存并写 `count_gain` / `count_loss`；跨仓批准只把调拨单改为 `executable`，库存变化发生在显式执行。

| POST/GET | `/api/v1/agents/sessions` | 智能助手会话；消息只调用受控工具 |

AI 功能只能用于问答、预警解释、报表建议或生成待审批草稿。AI **不得**直接修改库存、自动确认入/出库单、绕过 JWT/RBAC，也不得执行任意原始 SQL。

### 12.1 验收记录

- 后端 pytest 覆盖收货实收数量、出库复核后才扣库存、看板图表、用户/商品/库位写入、预警确认、助手查询不改库存。
- 前端收货确认、出库复核、用户管理和智能工作台为独立路由；看板展示真实汇总与 7 日柱状图；路由级分包将 Vue / Element Plus 拆出主包。

## 13. Redis、LangGraph、报表与 Docker

### 13.1 Redis 缓存

`REDIS_URL` 为空或连接失败时，后端使用进程内 `MemoryCache`。缓存键：

- `erp:dashboard:summary` / `erp:dashboard:charts:*`（TTL 约 30 秒）
- `erp:stock:*`（库存热点，丢失后从 MySQL 重建）
- AI 临时数据必须使用 `ai:` 前缀，禁止覆盖 `erp:stock:`

库存事实仍以 MySQL `SELECT ... FOR UPDATE` 为准。`apply_inbound`、`reserve`、`deduct_reserved`、`apply_count_adjustment`、`execute_transfer_line` 在写入后失效看板和库存缓存。

### 13.2 LangGraph 智能体

`POST /api/v1/agents/sessions/{id}/messages` 走 LangGraph 状态图：意图识别 → 库存查询 / 入出库分析 / 异常 / 草稿 / 审核编排。节点只调用白名单工具（`query_inventory`、`query_abc_report` 等），禁止 `execute_raw_sql`、`update_stock_balance` 等。无 LLM Key 时使用确定性关键词路由。

`GET /api/v1/system/runtime` 返回 `cache_backend`、`graph_engine=langgraph`、`inventory_source=mysql`。

### 13.3 ABC / 周转报表

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/reports/abc` | 按 `stock_ledger` 出库量帕累托 80/15/5；全 0 则按现存量 |
| GET | `/api/v1/reports/turnover` | 出库量 / max(现存量, 1) |
| GET | `/api/v1/reports/daily` | 近 7 日入库/出库量（仅 stock_ledger） |
| GET | `/api/v1/reports/weekly` | 近 4 周入库/出库量 |
| GET | `/api/v1/reports/picking-efficiency` | 拣货任务完成率 |

不扫描历史 `inbound_record` / `outbound_record`。

### 13.4 Docker Compose

仓库根目录 `docker-compose.yml` 启动 MySQL 8、Redis 7、backend、frontend。密码和 `SECRET_KEY` 用环境变量注入，不要写进仓库。Compose **不会**执行破坏性 `database/schema.sql`。后端入口只跑 Alembic `upgrade head`。

```powershell
docker compose up --build
```

前端容器把 `/api` 反代到 backend；构建时 `VITE_API_BASE_URL` 为空字符串，浏览器使用当前源。

### 13.5 验收记录

- 入库确认后看板 `stock_quantity` 必须更新，不能读到过期缓存。
- 助手工具名均在白名单，且带 `agent` 字段。
- ABC 份额合计为 1；单商品为 A。
- 前端 `/reports` 展示 ABC 与周转；助手标识为 LangGraph 多智能体。
