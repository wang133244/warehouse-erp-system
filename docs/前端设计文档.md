# 智能 ERP 仓管系统前端设计文档

> 版本：1.1  
> 日期：2026-09-08  
> 项目：智能 ERP 仓管系统 / Mega Star 仓储管理模块  
> 技术栈：Vue 3、TypeScript、Vite、Element Plus、Pinia、Vue Router、Axios、ECharts  
> 当前阶段：前端界面原型已实现并可启动预览；后端暂不实现，禁止使用假数据

---

## 1. 前端定位

前端目标是做一个“真实可用的企业仓管工作台”，不是静态展示页。它需要覆盖：

- 商品与 SKU 管理；
- 仓库、库区、巷道、货架、储位管理；
- 库存查询与库存流水；
- 收货入库、出库拣货、盘点、调拨；
- 预警、审批、审计；
- 数据导入结果查看；
- AI 智能工作台。

当前阶段只完成页面结构、视觉规范、组件边界、字段定义、交互流程和接口契约设计，不实现后端，不创建 Mock 数据，不导入前端 JSON 数据，也不模拟真实业务状态。页面需要展示内容时，只允许使用空状态、骨架屏、字段占位和静态说明。

前端工程当前可以作为“无后端界面原型”启动预览，但不代表业务系统已经可用；不得通过假数据制造“登录成功”“库存变化”“入库完成”或“审批通过”等业务结果。后端完成后，前端再接入 FastAPI，使用 MySQL 中的真实业务数据，并由 Redis 提供缓存、锁和任务状态支持。

前端不直接连接 MySQL，也不直接执行 SQL。

## 2. 设计原则

1. **企业后台优先**
   - 桌面优先，最小适配 1280×720；
   - 信息密度适中，表格清晰；
   - 操作路径短，常用功能一跳可达。

2. **页面只做展示和交互**
   - 页面负责输入、校验、确认和展示；
   - 库存扣减、状态流转、权限校验、事务控制都由后端负责；
   - 前端不重复实现库存规则。

3. **先读后写**
   - 第一阶段先完成查询、看板、列表、详情；
   - 再做入库、出库、盘点、调拨等写操作界面；
   - 写操作必须带确认弹窗和操作结果反馈。

4. **大表性能优先**
   - 库位 65,856 行、库存 57,623 行，必须分页或虚拟滚动；
   - 搜索输入做防抖；
   - 列表默认只加载第一页；
   - 导出功能后置。

5. **AI 只辅助，不直接执行**
   - AI 可以查询、解释、预警、生成草稿；
   - 不能直接修改库存；
   - 高风险操作必须进入人工确认或审批。

6. **无数据原型与真实接口分离**
   - 页面先调用接口类型定义或使用明确的“未接入”状态，不返回假数据；
   - 不创建 `src/mocks`，不写模拟登录、模拟分页、模拟审批和模拟库存变化；
   - 后端完成后，再由 `src/api` 通过 Axios 接入 FastAPI，页面组件尽量不改。

## 3. 技术选型

| 类型 | 选择 | 说明 |
|---|---|---|
| 框架 | Vue 3 + TypeScript | 组合式 API，类型清晰 |
| 构建 | Vite | 启动快，适合中后台 |
| UI 组件 | Element Plus | 企业表格、表单、弹窗、抽屉、标签页成熟 |
| 状态管理 | Pinia | 用户、权限、主题、全局加载状态 |
| 路由 | Vue Router | 页面导航与权限路由 |
| HTTP | Axios | 后端完成后统一接入 FastAPI；当前只设计请求类型和错误处理 |
| 图表 | ECharts | 库存看板、库位热力、作业趋势 |
| 测试 | Vitest + Vue Test Utils | 组件与工具函数测试 |
| 端到端 | Playwright | 后续做关键流程测试 |

页面元素：

```text

账号输入框
密码输入框
登录按钮
```

当前阶段只做界面、校验规则、加载态和错误态，不请求真实登录接口，不保存 token，不自动进入首页。

## 12. 当前阶段的数据与接口策略

当前阶段明确采用“无假数据界面原型”策略。前端可以先完成页面和组件代码，但不能为了让页面看起来有内容而创建虚构的商品、库存、单据、审批、预警、用户或 AI 回答。

### 12.1 当前允许的内容

- 页面标题、菜单、字段名、表头、筛选项和按钮；
- 真实业务流程对应的表单结构和校验提示；
- 空状态：`暂无数据`、`尚未接入后端`；
- 加载骨架、请求失败、无权限和服务未连接状态；
- 不包含业务事实的静态说明、页面草图和组件示例；
- TypeScript 类型、API 方法签名和请求/响应契约。

### 12.2 当前禁止的内容

- `src/mocks` 目录及任何 Mock 数据文件；
- 手工编写的商品、库存、入库、出库、审批和预警记录；
- 模拟接口延迟、模拟分页、模拟登录和模拟 token；
- 点击按钮后在前端伪造库存变化、单据状态变化或审批结果；
- 使用导出的 JSON、LocalStorage 或浏览器内存充当业务数据库；
- 页面直接连接 MySQL、Redis 或执行 SQL。

### 12.3 无后端时的页面行为

| 场景 | 页面表现 | 是否产生业务数据 |
|---|---|---:|
| 首次打开列表 | 显示表头、筛选区和空状态 | 否 |
| 后端未启动 | 显示“后端服务未连接” | 否 |
| 未登录访问业务页 | 显示登录要求或页面占位 | 否 |
| 点击新增/确认/审批 | 展示表单或二次确认结构；提交按钮置为未接入 | 否 |
| 点击查询 | 未接入接口时不伪造结果，显示空状态或未接入提示 | 否 |
| AI 工作台 | 展示输入区、回答区和引用区布局，不生成虚构回答 | 否 |

### 12.4 后端接入后的真实数据链路

```text
Vue 页面
  → src/api（Axios 请求）
  → FastAPI 认证、权限、业务服务
  → MySQL（业务事实和历史记录）
  → Redis（缓存、分布式锁、幂等键、任务状态）
  → 返回真实响应
```

后端完成后，页面只需要接入 `src/api` 的真实实现。库存计算、状态机、事务、审批和审计仍然由后端负责；前端不复制这些规则。

示例（仅定义契约，不执行请求、不返回假数据）：

## 16. 开发注意事项

1. **不要在前端连接 MySQL 或 Redis**
   - 当前阶段不接入数据库和缓存；
   - 后续只通过 FastAPI 接口访问真实数据。

2. **不要把库存规则写死在页面**
   - 可用量、锁定量、冻结量由后端计算；
   - 前端只展示。

3. **不要让 AI 直接修改库存**
   - AI 页面只能生成草稿；
   - 高风险操作必须走审批。

4. **大列表必须分页**
   - 不允许一次性渲染 6 万行。

5. **写操作必须确认**
   - 收货确认、出库完成、盘点审核、调拨提交都需要二次确认。

6. **保持中文界面**
   - 所有菜单、按钮、提示、错误信息统一中文。

## 17. 当前阶段的执行限制与运行方式

当前阶段已提交并实现页面结构、视觉样式、组件清单、路由规划、字段类型和接口契约。可以启动前端开发服务器查看界面，但不执行真实接口请求、不连接 MySQL/Redis、不导入假数据，也不模拟真实业务状态。

```bash
npm install
npm run dev -- --host 127.0.0.1
```

浏览器打开 `http://127.0.0.1:5173/dashboard`。当前可查看首页看板、商品、仓库、库存、入库、出库、盘点、调拨、预警、审批、数据导入、操作审计和 AI 工作台等页面。查询结果区保持空状态，写操作只打开界面或提示“后端接口尚未接入”。

5. 前端配置真实 API 地址、认证策略和错误码映射；
6. 完成联调前的数据权限和危险操作审批方案评审。

联调阶段的启动命令、环境变量、数据库连接配置和部署方式，待后端搭建完成后另行补充，不在当前文档中执行。
