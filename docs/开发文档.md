## 1. 系统定位

系统是面向真实仓储作业的 WMS 工作台，不是数据集展示页，也不是让 AI 直接改库的聊天机器人。

```text
商品 / 仓库 / 库位
        │
        ▼
  Mega Star 初始化库存（仅导入批次）
        │
        ▼
入库确认 ──► stock_balance.quantity ↑  + stock_ledger
出库分配 ──► reserved_quantity ↑
拣货确认 ──► 任务 picked
出库复核 ──► 单据 reviewed
出库完成 ──► quantity ↓、reserved ↓  + stock_ledger
盘点差异 / 跨仓调拨 ──► 审批后过账
```

硬边界：

| 必须 | 禁止 |
|---|---|
| 库存只在 `inventory_service` 里改 | 前端、助手、报表直接 `UPDATE stock_balance` |
| 写操作带 `Idempotency-Key` | 对已有 `erp_wms` 再跑 `database/schema.sql`（含 `DROP TABLE`） |
| 结构变更走 Alembic 增量迁移 | 迁移 `DROP` 表/列，或启用 `downgrade()` |
| 历史 `inbound_record` / `outbound_record` 只读 | 把历史收发货重放进当前库存 |

## 3. 架构（MVC）

后端与前端都按 MVC 拆分。`backend/app/api/v1/*.py` 与 `frontend/src/api/*.py` 仅为兼容再导出，新代码不要继续往壳文件里加逻辑。

```text
浏览器 Vue View
    │  fetch + JWT + Idempotency-Key
    ▼
FastAPI Controller（app/controllers）
    │  鉴权、参数、调用服务
    ▼
Service（app/services）
    │  状态机、RBAC、幂等
    ▼
inventory_service  ──唯一写库存──►  MySQL stock_balance / stock_ledger / audit_log
    │
    └── Redis（可选）：看板/可用量缓存约 30 秒
         运行日志：控制台 + backend/logs/app.log（带 request_id）
```

### 3.1 后端目录

```text
backend/app/
  controllers/     # HTTP 路由（Controller）
  services/        # 业务逻辑
  schemas/         # 请求/响应 DTO
  db/models/       # ORM
  agents/          # LangGraph：graph / llm / tools
  core/            # 配置、JWT、缓存、异常、中间件、运行日志
  dependencies.py  # 当前用户、角色、仓库范围、JWT 黑名单
  main.py          # 组装 FastAPI
backend/logs/              # 运行日志 app.log（不入库，勿提交）
backend/alembic/versions/   # 0001～0005 增量迁移
backend/scripts/            # 检查库、迁移、seed_roles、create_admin
backend/tests/              # pytest，默认 SQLite 内存库
```

### 3.2 前端目录

```text
frontend/src/
  views/           # 页面（View）
  controllers/     # 页面逻辑
  models/          # API 与类型（Model）
  components/      # 通用/业务组件
  config/pages.ts  # 菜单、字段、角色可见性
```

## 6. 鉴权、角色与幂等

### 6.1 JWT

- 登录：`POST /api/v1/auth/login` → `access_token`
- 载荷：`sub`、`username`、`roles`、`jti`、`iat`、`exp`
- 密码：PBKDF2-SHA256 + 独立盐
- 请求头：`Authorization: Bearer <token>`
- 退出：`POST /api/v1/auth/logout` 把 `jti` 写入缓存黑名单（TTL = 剩余有效期）；前端同时清 `localStorage`
- 刷新页面：有 token 则 `GET /api/v1/auth/me` 恢复会话；401 则清登录态

### 6.2 角色

| 角色码 | 前端菜单 | 典型写权限 |
|---|---|---|
| `admin` | 全部，含系统管理 | 用户、导入 CSV、全部作业 |
| `warehouse_manager` | 无系统管理 | 商品/仓库/库位、审批 |
| `warehouse_operator`（兼容 `operator`） | 无系统管理 | 建单、收货、分配、拣货、盘点录入、同仓调拨执行 |
| `viewer` | 仅总览、资料、库存、预警、报表、助手 | 只读；导出允许 |

非管理员必须绑定 `user_warehouse_scope`。创建人不能审批自己的盘点差异或跨仓调拨。驳回必须填意见。

前端：`canAccessPath` / `visibleMenuGroupsFor` / `canPerformAction`（`frontend/src/config/pages.ts`）与路由守卫一起拦截。后端 `require_roles()` 是最终闸门。

### 6.3 幂等

所有改变库存或单据状态的写请求：

```http
Idempotency-Key: <用户侧唯一键>
```

按「用户 + 键」复用第一次响应，避免重复确认、重复预留、重复扣减。

## 7. 库存事务（唯一写入口）

实现：`backend/app/services/inventory_service.py`。

```text
available = quantity - reserved_quantity - frozen_quantity
```

| 动作 | 库存变化 | 流水 |
|---|---|---|
| 入库确认 `apply_inbound` | `quantity += n` | `inbound` |
| 出库分配 `reserve` | `reserved += n`（可用不足 409） | 无数量流水 |
| 出库完成 `deduct_reserved` | `quantity -= n` 且 `reserved -= n` | `outbound` |
| 盘点过账 `apply_count_adjustment` | 按差异加减；审批中冻结 | `count_gain` / `count_loss` |
| 调拨执行 `execute_transfer_line` | 源出、目标入 | `transfer_out` / `transfer_in` |

并发：MySQL `SELECT ... FOR UPDATE` + 进程/Redis 锁。SQLite 单测不能证明行锁，压测必须用独立 MySQL。

## 8. 业务状态机

**入库**

```text
draft --确认收货--> confirmed
```

**出库 / 拣货**

```text
出库单：draft --分配--> allocated --拣货齐--> picked --复核--> reviewed --完成--> completed
拣货任务：allocated --确认--> picked （完成出库后 completed）
```

**盘点**

```text
draft / counting --提交--> 无差异 completed
                      └► 有差异 pending_approval --同意 applied / 驳回 rejected
```

**调拨**

```text
draft --提交--> 同仓可执行；跨仓 pending_approval --同意后执行
执行：源库位出、目标库位入，各写一条流水
```

任一步失败则单据、库存、流水、审计同一事务回滚。

### 9.7 智能助手

| 方法 | 路径 | 说明 |
|---|---|---|
| POST/GET | `/agents/sessions` | 新建 / 列表 |
| POST/GET | `/agents/sessions/{id}/messages` | 提问 / 历史 |
| POST | `/agents/sessions/{id}/clear` | 清空消息 |
| DELETE | `/agents/sessions/{id}` | 删除会话 |

助手只调用白名单工具，**禁止**原始 SQL 和直接改库存。可生成入/出库/盘点**草稿**，必须到业务页人工保存。会话按用户隔离：`agent_session.user_id` 绑定登录用户，消息只属于一个 `session_id`；换用户或换会话不会带上别人的 history。运行日志带 `user_id` / `session_id`，访问他人会话记 `session denied`。

白名单：`query_inventory`、`query_alerts`、`query_approvals`、`query_dashboard`、`query_abc_report`、`query_turnover_report`、`query_daily_report`、`query_weekly_report`、`query_picking_efficiency`、`format_table`、`create_inbound_draft`、`create_outbound_draft`、`create_counting_draft` 等。

SKU 匹配支持 `SKU-…` 与 Mega Star 的 `MS-…`。多行结果自动 Markdown 表；也可说「制成表格」。有 DeepSeek Key 时先规划本轮（意图、SKU/库位/数量、是否沿用上一句 SKU），再改写答案；失败回退关键词。同一会话可以说「这个还有多少」接上上一句 SKU；缺 SKU 会追问，不再倒全部库存。低库存、预警、待审批会附下一步建议，仍不直接改库存。

## 12. 运行日志

与页面「操作审计」不同：审计进 MySQL `audit_log`；运行日志进控制台和（可选）文件，给开发/运维排障。实现：`backend/app/core/logging.py`，启动时 `create_app()` 调用 `configure_logging()`。

### 12.1 看哪里

| 环境 | 位置 |
|---|---|
| 本机开发 | 启动 uvicorn 的终端 + `backend/logs/app.log` |
| Docker Compose | `docker compose logs backend`（`LOG_TO_FILE=false`） |
| 自动化测试 | 不写文件（`LOG_TO_FILE=false`），由 pytest `caplog` 捕获 |

文件按天滚动，保留 14 天。目录可用 `LOG_DIR` 覆盖，空则 `backend/logs`。该目录已加入 `.gitignore`。

格式：

```text
2026-09-16 10:20:00 INFO [trace-42] erp.http: GET /api/v1/inventory/balances status=200 duration_ms=12.3
```

`[trace-42]` 与响应头 `X-Request-ID`、错误 JSON 的 `request_id`、以及 `audit_log.request_id` 相同（写审计时若未显式传入则取当前请求 ID）。客户端也可自行传入 `X-Request-ID`。

### 12.2 Logger

| 名称 | 内容 |
|---|---|
| `erp.runtime` | 日志系统就绪、应用创建 |
| `erp.http` | 方法、路径、状态码、耗时；`/health`、`/docs` 为 DEBUG |
| `erp.auth` | 登录成功/失败、注销、JWT 黑名单命中（不记密码和 token） |
| `erp.inventory` | 入库、预留、出库、盘点过账、调拨摘要；锁超时 WARNING |
| `erp.agent` | `user_id` / `session_id`、history 条数、意图、工具名、是否草稿；越权 `session denied`；LLM 失败 WARNING |
| `erp.cache` | Redis 不可用并回退内存 |

级别：`LOG_LEVEL`（默认 `INFO`）。业务拒绝（库存不足等）WARNING；未捕获异常 ERROR，对外 `INTERNAL_ERROR`，不把堆栈或密钥返回给浏览器。

禁止写入：密码、JWT 全文、数据库口令、管理员口令、助手整段工具结果。

### 12.3 和审计怎么一起用

1. 前端报错里抄 `request_id`（或响应头 `X-Request-ID`）。  
2. 在 `app.log` / 终端搜该 ID，看访问行和 WARNING/ERROR。  
3. 管理员再打开「系统管理 → 操作审计」或查 `stock_ledger`，核对谁改了库存。

## 13. 错误与安全约定

统一错误 JSON（中间件）：`code`、`message`、`request_id`，以及对应 HTTP 状态。常见：`401` 令牌无效/已注销，`403` 无角色或仓库范围，`409` 库存不足/状态不允许/用户名已存在，`422` 校验失败，`500 INTERNAL_ERROR` 未捕获异常（详情只在运行日志）。

安全清单：

- 密钥、数据库口令、管理员密码不进仓库
- 前端只打 FastAPI
- 助手不能声称「已经入库/已经改库存」
- 停用商品/库位后不可用于新入出库
- 运行日志不记录密码、JWT 和数据库口令
